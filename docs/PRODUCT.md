# 产品与验收

## 问题与目标

企业客服的风险不只是回答不流畅。过期资料、套餐条件不明、越权查询、随口承诺退款和没有下文的转人工，都可能使一个聊天 Demo 无法交付。本实验室用虚构业务验证这些边界，展示产品经理的范围定义、知识治理、工程验收与交接能力，而非假装已经验证真实企业需求。

目标用户是需要把知识库客服从原型推进到验收的 AI PM、实施工程师与知识负责人。这个画像是设计假设，尚无访谈证明。

## 业务决策

| 触发 | 系统行为 | 业务原因 |
|---|---|---|
| 有有效公开知识 | 规则引用；可显式起草模型回答 | 先给来源，避免无依据编造 |
| 套餐不明的退款问题 | 澄清；同会话补充条件 | 避免把月付规则泛化到企业合同 |
| 价格、合同、年付、赔偿、真实订单 | 人工交接 | 当前没有交易权限和身份核验 |
| 私有名单、敏感资料、指令绕过 | 有限规则拒答 | 内部知识不进入客户检索或模型上下文 |
| 过期或冲突来源 | 停止回答并转人工 | 让知识负责人确认，不让模型自行选择 |
| 发布知识 | 客户端预览、服务器门禁、冻结新版本并保存回归 | 知识更新也是一次产品发布 |
| 模型失败或引用不合法 | 保留真实失败与原候选；来源规则答案分开 | 不用兜底覆盖失败以美化完成率 |

当前规则不是通用语义分类器，不覆盖所有表达、攻击与多轮对话。澄清衔接只处理有限退款条件，不承诺完整对话理解。

## 功能验收

六个工作区：总览、客服、知识、工单、回归、交付。回答附有效来源快照；知识新版本不修改旧回答。工单状态只能按 queued → accepted → resolved 转换，需处理说明及 revision。记录保存于 SQLite，刷新恢复。知识失败回归不能发布，历史回退创建新版本。JSON 交付包包括业务、知识、对话、工单、报告、清单及 SHA256 完整性标记。

模型输出模式只用于语义草稿：限制输出 schema，引用 ID 和原文摘录校验，最终由操作者记录接受或拒绝。字面引用并不自动证明答案被来源蕴含。人审不是独立专家盲审。

## 评测协议

固定题集 `synthetic-boundary-20-v1`，材料日期 2026-10-06。先冻结题目、期望出口、必要来源、关键包含/排除条件；规则运行不调用模型。旧检索有意保留已退役资料优先、缺时效与权限筛选的缺陷。它用于展示回归如何捕获问题，不是公平竞品效果实验。

报告按用例保存两组原始回答、引用与失败原因，统计通过、路由正确、无效来源案例。合成题集 20/20 不外推到真实业务。真实模型两条试用/退款问题单独报告，不混入规则分母，也不计算广义模型准确率。当前没有人工介入率、客户转化、真实工单解决率或长期服务成本结论。

## 发布与后续优先级

公开浏览器演示没有共享数据和模型凭证；完整本机版用于单用户实施与审阅。生产前必须补身份与权限、客户授权数据、真实客服渠道、备份恢复、业务负责人签字、供应商数据处理规则及容量/成本验收。

后续优先验证：真实用户能否独立走完流程；扩充措辞与对抗题集；扩大真实模型样本并独立审阅；真实 CRM 沙箱联调。没有这些外部输入时，不能靠继续写代码宣称已经完成客户交付。
